# Venue open interest: collection and the Event #15 retest

Research only. No signal design, no score, no weights, no threshold of our own, no methodology version, no V1 or
Candidate #1 change, no production write, no deployment.

This continues `RISK_REGIME_EVENT15_RESEARCH.md` (commit `0abb76d`), which concluded **SOURCE GAP STILL
MATERIAL** because venue open interest (OI) was missing. The earlier results are unchanged:
`results/risk_regime_event_research.json` is regenerated byte-for-byte by the default run.

## Verdict

**The source gap is reduced, not resolved.** Binance BTC open interest and funding are now collected:
- verified history from 1 Jan to 7 Oct 2026, with no gaps;
- every file checked against Binance's published SHA-256 checksum.

On that data, with the declared rules unchanged:
1. **OI was not abnormal before PRED-1125 (27 Sep 12:01 UTC), and not before PRED-1124 (09:01) either.** Level
   and 1 h / 6 h / 24 h / 72 h changes were all inside their own trailing 7-day ranges, and so was Binance
   funding.
2. **Leverage was not building before Event #15. It had already been flushed.** Coin OI fell from about 106.7k
   BTC (23 Sep 00:00) to 94.6k at the boundary. That includes a −5.5 % / 6 h drop at 16:00 on 23 Sep, as BTC
   fell from about 85.8k to 84.0k. That flush *was* abnormal when it happened, 3–4 days before the boundary. By
   the boundary it was outside every declared window. Only a post-hoc 7-day view still shows it (−13.2 %, the
   0.46th percentile of 90 days).
3. **That pattern does not generalise.** A large 7-day OI drop came before failed and correct V1 UP calls on the
   same number of days (6 and 6). Under the declared rule, the OI dimensions are abnormal about as often before
   failed V1 UP calls as before correct ones (58 % vs 55 %; base 55 %).
4. **Contemporaneous only.** OI *rose* into the event (94.1k at 00:01 → 95.3k at 03:01 → 95.9k at 04:01) while
   BTC fell, not abnormally. OI then dropped after the event (93.0k at event + 24 h, abnormally low:
   POST-EVENT).

**The available evidence does not establish that Event #15 was forecastable from venue open interest.** The
one dimension the previous report ranked as potentially decisive shows no pre-boundary build-up. That weakens
the "leverage build-up and unwind" mechanism for this event.

The gap is not fully closed for two reasons:
- **Bybit:** still refused (HTTP 403) from every location available to this work, so no cross-venue check.
- **Liquidations:** still have no €0 historical source.

**Instrument and units.**
- Binance USD-M BTCUSDT perpetual.
- `open_interest` = `sum_open_interest` in **BTC** (coin), the measure used for leverage.
- `open_interest_usd` = `sum_open_interest_value` in **USD** notional. It moves with price, so it is kept
  separate and never mixed with coin OI.
- Funding is a rate per 8 h settlement. It is not comparable one-to-one with Hyperliquid's hourly funding (the
  Hyperliquid floor 1.25e-5/h ≈ 1e-4 per 8 h).
- Cross-check: at the boundary, 94,566 BTC and $8.02 bn imply BTC at about 84.8k. That matches the independent
  Hyperliquid close (84,881).
- The archive's other columns (top-trader and taker long/short ratios) are kept raw only and not analysed.

**Availability rule.** A 5-minute archive value is treated as available at `create_time + 5 min`.
- The same statistic was served live by `openInterestHist` (period 5m). The daily file itself appears after the
  day ends.
- Not verified here: whether archive values equal what the live API served at the time. The REST API is
  blocked, so no overlap comparison was possible. The SHA-256 match proves the files are Binance's own, not
  that they match the live API.
- Funding is available at its settlement `calc_time`.

**Deadline.** The ~27 Oct deadline applied to the REST endpoint's 30-day retention. The archive covers the
event regardless.

## 5. What OI adds beyond V1

- V1 has no open-interest source. Its leverage view is Hyperliquid funding, which sat on its floor (read as 50)
  throughout.
- OI adds visibility of *when leverage is flushed*. On 23–24 Sep it showed a large deleveraging that V1 could
  not see.
- For Event #15 that information was 3–4 days old at the boundary, and it did not distinguish failed from
  correct calls historically.
- Its present research value is regime context, such as "post-flush, low-OI regime". It is not a pre-event
  warning.
- Class: NEW_SOURCE (no pre-event support yet).
